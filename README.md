# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 照明灯具受控台账

`廊内照明运维` 单独走 `frontend/src/api/lighting-ledger.ts`，针对「归属没人把关、落库不全、
台账不留操作人」做了收口，附属存储键为 `urban-utility-tunnel:lighting-ledger`：

- **按岗位与归属开放**：顶栏可切换账号。仅本舱室「照明责任岗」（综合/电力/燃气/水信各一岗）
  能提交本舱灯具的损坏登记、补录与状态流转；外包、值班管理员、检修班及其他舱岗位对照明台账
  只读。越权提交一律拒绝，提示写明归属冲突（归属舱室、责任岗、当前账号授权范围）。
- **校验拦截**：灯具编号由系统分配（`ZM-舱码-三位序号`），禁止手填；安装位置必须落在舱室
  位置目录内且与台账一致，位置对不上、同位置重复占用一律不许入账。
- **整笔事务**：损坏登记支持多盏整笔提交，归属冲突、编号不存在、重复登记任何一条命中都整笔
  退回（台账、检修待办一个字不写），退回原因落进遗留清单；全部通过才由 `commitAtomic`
  多仓一次落库。同一盏灯反复登记只认第一次那份，后到整条退回、条数不叠加。
- **检修联动**：登记成功的灯具在「设施检修管理」生成 `MAIN-<灯具编号>` 灯具更换待办，照明
  检修班从那边接单（开工→完工），状态双向回写；照明台账与检修清单读同一份存储快照，
  待更换数与待办条数始终一致。
- **上线归置（一次性、幂等）**：首次打开自动把旧台账按「舱室固定顺序（综合/电力/燃气/水信）
  → 舱内安装位置目录顺序」重新排号，舱室内从 `001` 连号、缺号自然补齐；编号重号只留验收
  最早一份，同舱同位置重复只留最早一份，位置非法的整条退回遗留清单。有验收日期的按验收日期
  归位，早年没有登记时间的按最早一次遗留动作推定；原编号与全部历史动作保留在审计轨迹里。
- **留痕**：每盏灯的历史动作、登记人、岗位、时间都在详情面板可查；上报问题同步进照明入口与
  设施检修管理入口两处的遗留清单，两处条数一致。
- **规则验证**：`node scripts/run-verify.cjs`（在 `frontend/` 下执行）覆盖归置、归属、
  重复、整笔事务、补号、检修同步、同源一致与重置幂等共 59 条断言。
- 调试重置：`resetLedger()` 会清掉归置结果并按示例遗留数据重新归置。
